# 10 流程与数据欠账

依据：第二轮走查。以下四项动状态机或数据模型，不宜顺手改，单独立项。
结论见末尾：地基不重写，按项还债。

## D1. 手写豁免跨挂载丢失

- 现状：`WorkspaceView` 的 `handwriteBypass` 是局部 `useState`，
  `resetKey` 重挂后丢失，用户被拦回配模型页。
- 目标：豁免状态上移到 App 层（与书籍选择同级），重挂、切分区不丢失；
  仅在重置/恢复出厂时清除。
- 验收：无模型点“先手写”后，切分区、触发重挂不回弹配模型页；
  重置后回到未豁免态；单测覆盖状态保持。

## D2. 专注模式保留返回入口

- 现状：`WritingEditorToolbar` 专注模式隐藏返回键，沉浸下唯一出口不可见。
- 目标：专注模式左上保留低透明度悬浮返回，hover 显形；
  Esc 退出专注，并在专注提示区注明。
- 验收：专注下可见可点的返回入口；Esc 行为有界面提示；退出专注不丢正文。

## D3. 斜杠建卡改走审批

- 现状：`GlobalAssistant` 的 `/角色` 等快捷命令直调落库，
  与 Agent 写提案（待审箱）两条标准不一。
- 目标：快捷建卡同样产出 proposal 进 `ApprovalHost`（复用
  `core.card.generate` 管线），一批准即落库，保持快捷体验；
  拒绝无残留、无历史污染。
- 验收：`/角色` 不再直接落库；待审箱可批可拒；
  拒绝后项目数据与聊天记录干净；单测覆盖批准/拒绝两径。

## D4. 数据层中文值改枚举

- 现状：角色 `role/gender` 的 option value 与默认值是中文
  （`主角/未知`），匹配靠 `includes('主'/'反'/'配')`，
  时间线影响度靠 `includes('重大'/'关键'…)`，
  英文界面下数据与逻辑耦合中文；`displayLabels.ts` 已是补丁式映射。
- 目标：`shared/types` 引入英文枚举 id
  （角色定位/性别/影响度），存储与比较全用枚举，
  显示经 `displayLabels` + 字典；斜杠命令保留中英别名（仅输入层）；
  启动期 normalize 旧中文值到枚举（附单测；现无真实用户数据，
  迁移函数仍保留）。
- 验收：切换英文后数据一致、匹配与语言无关；
  旧中文数据打开后自动归一化；斜杠中英都可用；
  全库零 `includes('主')` 式中文匹配（输入层别名除外）；
  相关单测全绿。

## 结论：不重写，按项还债

- 地基评估（对标 OpenCode/Cherry Studio/SillyTavern/novelWriter）：
  已具备分层 `core/`、工具契约+三档审批、会话事件溯源、
  技能渐进加载、MCP 双向、FTS+向量检索、多渠道网关、
  Anthropic 缓存断点、中英字典锁线、覆盖率门禁——
  这些正是成熟项目的标配件，重写等于丢掉 630+ 用例资产。
- 真差距（按优先级）：数据层 i18n（本篇 D4）→ 插件生态
  （机制有、示例与文档缺）→ E2E/UI 断言（仅冒烟）→
  包体积（单包 2.3MB，未拆分）→ 发布工程（签名/自动更新）。
