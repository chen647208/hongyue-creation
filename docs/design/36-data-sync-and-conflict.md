# 36 数据同步与冲突

## 背景与问题

有两套同步语义：实时协作（Yjs，同机/局域网中继）与异步同步包（`core/sync` 协议 + bundle 文件）。异步同步的落库实现直接以原始 SQL 文本调用主进程数据通道，而主进程只接受 `shared/sql/catalog.ts` 内的语句 id，未知 id 直接报错，导致该功能实际不可用；同时缺少云/网盘类传输，以及用户可感知的冲突与丢稿提醒。

## 目标

- 修好同步包读写的落库路径，使其不再绕过语句单源。
- 提供可选的传输层（本地文件、WebDAV、S3 兼容），用于把同步包送达另一端。
- 冲突与自动恢复对用户可读：出现冲突副本、自动恢复、导入覆盖前都显式告知。

## 非目标

- 不同步"活库"（数据库文件本身）；只同步导出物，避免第二真相源。
- 不做账号体系与云托管；传输是用户自备的地址与凭据。
- 不改实时协作（Yjs）形态。

## 设计

1. 修同步包落库：读取全书实体改为走仓储接口（按书读实体或经项目桥投影），不再拼接 SQL 文本；主进程侧维持"只认语句 id"的边界。
2. 传输协议：定义一个传输接口（推送/拉取/列举/删除），实现三类——本地目录（已有外部镜像可复用）、WebDAV、S3 兼容。凭据存系统钥匙串，渲染端只持引用。
3. 同步流程：本地导出 bundle → 传输层上传；拉取远端 bundle → 合并（沿用现有冲突副本策略，禁用 LWW）→ 应用插入集；全过程产出可读报告（各实体增删改与冲突数）。
4. 冲突与恢复提示：出现冲突副本、应用替换、合并失败时，用统一对话框给出"保留本地 / 采用远端 / 打开冲突副本"三选；自动恢复成功要留一条可查记录。
5. 触发：手动为主；可选"退出时导出到本地/网盘目录"，失败下次启动提醒。

## 验收

- 导出同步包后能在另一端导入，章节与实体齐全；重复导入幂等，不产生重复书。
- 两端各自改动同一章后合并：生成冲突副本，原稿与改动都不丢，报告列出冲突条目。
- WebDAV 与 S3 至少各有一个连通测试入口，失败给出可读原因。
- 冲突/恢复提示在键盘与读屏下可操作。

## 风险

- 远端覆盖本地：合并前必须先本地快照，且默认不删除本地数据。
- 凭据泄露：传输凭据与 AI Key 同走钥匙串，日志与报告不得出现明文。
