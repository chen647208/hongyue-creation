# 33 动效规范

## 目的

动效只用于**反馈**与**空间连续**，帮助用户理解状态变化与位置关系；不做炫技、不拖慢操作。原则见 `AGENTS.md` 第十条。

## 允许的动效

- 出现/消失：面板、弹层、提示的淡入淡出（120–160ms）。
- 空间连续：列表/看板重排、面板开合时的位移过渡（150–200ms，`ease-out`）。
- 反馈：按钮按下、开关切换、拖拽落点的短促高亮（≤120ms）。
- 加载：骨架/进度保持已有实现。

## 禁止

- 长时间或阻塞操作的动画（>300ms 的交互前置动画）。
- 大幅位移、弹跳、旋转等与信息无关的装饰。
- 在滚动、输入路径上的动画（避免掉帧）。

## 可访问性

- 一律尊重 `prefers-reduced-motion: reduce`：命中时关闭位移与淡入，仅保留瞬时状态切换。
- 动效不得作为唯一的状态指示（须同时有文字/图标/颜色变化）。

## 实现约定

- 统一用 CSS 变量定义时长与缓动（`--motion-fast/-base`、`--motion-ease`），组件只引用变量。
- 不引入动画库；用 Tailwind `transition-*` 与自定义 keyframes。
- 视觉回归（`e2e/visual.spec.ts`）截图前等待动效结束；新增动效如影响快照，先刷新基线再提交。

## 验收

- 键盘与减少动效偏好下功能无差异。
- 视觉快照稳定（无偶发差异）。
