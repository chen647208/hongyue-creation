# 40 生态与运行时能力

## 背景与问题

插件机制（清单、依赖、权限、沙箱、签名、MIT SDK）已完备，但没有分发渠道与市场；AI 只有单助手单会话；MCP 只对外暴露读工具与两类资源，自举回路未闭合；缺联网搜索与翻译这类通用能力；本地推理只能接外部 Ollama，不能自带运行时。

## 目标

- 插件可发现、可安装、可更新：有目录与版本、签名校验、一键安装/停用/卸载。
- 助手可多会话、多人格：并行任务、会话归档与恢复。
- MCP 自身能力面补全并自举：内置助手经同一 MCP 面读写，写操作走同一待审箱。
- 通用能力以插件形态提供：联网搜索、翻译；可选本地推理运行时。
- 一切能力可关闭，关闭后纯写作路径完整。

## 非目标

- 不做插件收费与账号。
- 不把联网搜索/翻译做成核心内置（避免体积与合规负担），走插件。

## 设计

1. 插件分发：定义目录索引（列表/版本/摘要/签名/兼容 host 版本），索引整份 payload 需带 detached 签名（同级 `catalog.sig`，ed25519/cosign），主进程按信任键清单验签，校验失败拒绝使用；安装时校验签名与来源白名单（空白名单 fail-closed，显式允许任意来源才放行），落 userData/plugins；更新走差分，失败回滚到上一版本；卸载清理配置与缓存。
2. 多助手：会话独立数据（消息、上下文、任务），可命名、归档、搜索；同一时刻允许多个后台任务（已有串行任务服务的上限按需放开），顶栏统一指示与中止。
3. MCP 资源面：补实体、章节、索引、视图等资源的读取与模板，使外部 agent 与内置助手看到同一份能力；写意图统一进待审箱，应用与落库由同一执行器完成。
4. 联网搜索/翻译：作为插件（逻辑型沙箱 + 受控网络门）实现，结果作为不可信输入注入；核心只提供工具契约与审批位。`examples/plugins/web-search` 给出资源型示例（`permissions.network` + 技能声明 `core.net.fetch`），演示联网白名单与围栏接线；禁用后手动路径完整。
5. 本地推理：提供"本地运行时"接入层（进程管理、模型列举、OpenAI 兼容本地端点），运行时不随包分发；关闭即回落远程网关。
6. 可执行贡献形态：导出渲染器与脚本层的描述符协议（入口函数引用、纯度/同步性声明、能力白名单、输入输出 schema）见 49 篇；本层负责分发、权限门与沙箱运行时，按该协议接入执行。

## 验收

- 从目录安装一个签名插件后其贡献生效，停用后回滚干净；篡改签名的包被拒。
- 目录索引整份 payload 的 detached 签名校验失败即拒绝使用；空白名单默认拒绝安装，显式允许任意来源才放行。
- 联网搜索/翻译示例插件经 `permissions.network` + 网络门白名单 + 不可信围栏取外部资料，禁用后纯写作路径完整。
- 两个助手会话可并行，各自上下文互不污染；归档后可恢复。
- 外部 MCP 客户端能列出并读取资源，写请求进待审箱并在批准后落库。
- 关闭全部插件与本地推理后，纯写作、导出、加密、检索仍完整可用。
- 关键路径（安装/校验、会话隔离、待审箱落库）有单测或 E2E。

## 风险

- 供应链：目录索引与包都需签名校验，来源白名单默认拒绝未知来源。
- 本地推理进程安全：以子进程隔离，限制文件与网络访问面。
