# 38 修订、批注与关联

## 背景与问题

出版与审校场景需要可逐处接受/拒绝的修订与行内批注，现在只有章节级快照与历史 diff，改稿只能靠人眼找差异；实体之间只有单向跳转，缺"谁引用了它"的反查；角色"登场章节"与"正文→章纲"这类派生信息没有回写入口。

## 目标

- 修订标记：正文改动以可接受/拒绝的标注呈现，支持全部接受、全部拒绝、逐处处理。
- 行内批注：任意选区挂批注，可回复与解决，批注不进入导出正文。
- 关联反查：正文与实体互相引用时能看到反向引用列表，并可跳转。
- 派生回写：一键把某角色的登场章节列出并可跳转；一键从正文提取章纲草稿。

## 非目标

- 不做多人实时评论与权限（协作 B 档不在计划内）。
- 不做三方合并算法；修订是单人改稿的差异视图。
- 行内批注不参与字数与导出内容。

## 设计

1. 修订标记：编辑器记录"基线 → 当前"的字符级差异（基线取章节快照）；删除与插入以装饰呈现，逐处可接受/拒绝；接受即写回当前文档并落盘，拒绝即还原该段。
2. 批注：以编辑器装饰携带批注 id，批注正文与状态存在侧车数据（按章节）；解决后从正文装饰移除但保留历史；导出时过滤批注标记。
3. 反向引用：索引器已产出硬链接与回链，补一个反查面板——给定实体列"被谁引用"、给定章节列"引用了哪些实体"，双向可跳。
4. 角色登场：按角色名在章节中匹配（已有按名匹配能力），产出"角色 → 登场章节列表"，可跳转；角色卡增加"登场章节"区块。
5. 章纲提取：对选定章节范围用 AI 归纳出章纲草稿，写入细纲待用户确认；与现有"大纲→细纲"方向互补。
6. 数据边界：修订基线与批注是正文的标注层，不改变六实体存储；导出与统计只看正文。

## 验收

- 改一段后能逐处接受/拒绝，全部接受回写后正文正确、字数与导出随之更新。
- 批注可增删改与解决，导出不含批注文本。
- 反向引用面板对一条已知引用给出一致结果（与索引器一致）。
- 角色登场列表与正文实际出现一致；章纲提取产出草稿且不直接覆盖既有细纲。
- 单测：差异计算、接受/拒绝回写、批注过滤导出、反查结果。

## 风险

- 大章节差异计算开销：基线按章节快照、差异惰性计算并缓存。
- 批注与修订叠加时的定位漂移：以 id 锚定，不接受纯位置锚定。
